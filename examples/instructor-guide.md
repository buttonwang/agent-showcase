# 讲师指南 · 业务助手智能体培训

## 课程目标

让零代码基础的学员,在 1-2 天内能用 Codex 做出一个可用的业务网页应用,覆盖 4 种典型场景(A/B/C/D)。

学员交付物:

- 1 份 PRD 文档(版本号 ≥ v0.1)
- 1 个单文件 HTML Demo(双击即开,CRUD 可用)
- 1 份 `checklist-<产品名>.md`(全勾)
- 1 份 `CHANGELOG.md`(记录所有改动)

## 课时建议

| 时段 | 时长 | 形式 | 内容 |
| --- | --- | --- | --- |
| 上午 1 | 0.5h | 讲解 | Skill 是什么 / 能做什么 / 不能做什么 |
| 上午 2 | 0.5h | 演示 | 讲师投影跑 walkthrough-hr-recruitment.md,展示 4 场景 |
| 上午 3-4 | 1.5h | 实战 | 学员选真实业务,跑阶段一/二/三 |
| 下午 1-2 | 1.5h | 实战 | 学员跑 4 场景(用 student-checklist) |
| 下午 3 | 0.5h | 复盘 | 学员展示成果,讲师点评 + 评分 |
| 下午 4 | 0.5h | 答疑 + 收作业 | 讲师答疑,收 checklist 和 demo 打包 |

合计:5 小时(1 天)
升级版:加 1 天做「跨部门联合 demo」(可选)

## 课前准备

讲师侧:

- [ ] 自己跑一遍 walkthrough,确保熟悉 4 场景
- [ ] 准备 3-5 个真实业务场景(自己行业的例子)
- [ ] 把 3 个参考 demo 在自己机器上跑通,准备好截图/录屏(备用)
- [ ] 打印评分量表(给学员每人一份)

学员侧:

- [ ] 装好 Codex(桌面版 / 浏览器扩展)
- [ ] 拿到 Skill 包(目录或 zip)
- [ ] 跑 `python work/smoke_test.py`,期望 78/78
- [ ] 选一个真实业务,自己想好 3 轮对话内容

## 讲解要点

### 第一段:Skill 是什么(15 分钟)

- Skill = 给 Codex 读的「说明书」,让 Codex 知道「你被启用后该怎么干活」
- 这个 Skill 的工作流:4 阶段 + 4 场景
- **学员的角色:不是程序员,是「业务产品经理」**
- 强调:不需要懂 HTML / CSS / JS

### 第二段:演示(20 分钟)

- 用 `walkthrough-hr-recruitment.md` 投影
- 重点演示:
- 30 秒场景判断
- 三件套(PRD / 代码 / CHANGELOG)一起改
- 场景 C 的冻结老版本 + 迁移函数
- 边演示边让学员看 checklist 怎么用

### 第三段:学员实战(60-90 分钟)

- 每人选一个真实业务(不能是 HR,跟讲师业务不同)
- 复制 `student-checklist.md` → `outputs/checklist-<产品名>.md`
- 边做边勾,卡了就举手
- 讲师每 15 分钟巡场一次,问「卡在哪了」

### 第四段:复盘 + 评分(30 分钟)

- 抽 2-3 个学员 5 分钟演示
- 讲师用 `instructor-rubric.md` 现场打分
- 学员也用同一份量表互评,看评分标准是否一致

## 常见学员错误(讲师提前知道怎么救场)

| 错误 | 救场话术 |
| --- | --- |
| 一句话需求 | 「你是 HR,你日常最头疼哪 3 件事?用大白话告诉我」 |
| PRD 写到对话里 | 「PRD 必须写文件,这样能发给组长看,你写进对话组长看不到」 |
| CRUD 是空架子 | 「你点一下新建按钮,看看有没有弹窗,有没有保存反应」 |
| 场景 C 没冻结 | 「你上次写好的 v0.3 数据呢?如果你现在重写会丢吗?」 |
| 字段没版本号 | 「你给 5 个同事看,谁知道你这是哪一版?」 |
| 主导航放右侧 | 这是历史教训,直接演示「培训里曾经有学员这么做,被骂了」 |
| 用了 emoji 图标 | 「你打开 dev tools 看一下,这个图标在屏幕阅读器里念不出来」 |

## 评分

用 [instructor-rubric.md](instructor-rubric.md) 评分:

- 90+:优秀,可直接交付生产
- 75-89:良好,需要少量打磨
- 60-74:合格,需要中等打磨
- < 60:不合格,需要返工

讲师不只看最终交付物,**要看 checklist 过程**——一个 60 分交付物 + 完整 checklist,比 90 分交付物 + 空白 checklist 学得多。

| 0.5 天 | 只做阶段一/二/三,不讲 4 场景(适合高管/管理层体验) |

## 讲师 FAQ

**Q:学员电脑装 Python 失败怎么办?**

A:本 Skill 的 smoke_test 用 Python(Codex 自带)。如果学员 Python 没装,跳过 smoke_test 也能用 Skill——但讲师没法验证安装。备选:让学员跑 `node -v` 看 node 装了没,作为粗略验证。

**Q:学员的 Codex 版本太老,不识别 Skill 怎么办?**

A:让学员更新 Codex 到最新版本。Skill 触发词可能不兼容老版本。

**Q:学员选的「业务」太复杂,做不完怎么办?**

A:让他砍需求。一个 1 天培训能做完的「业务」必须有:

- 1-3 个实体(比如「候选人」+「面试评价」)
- 单一用户角色
- 简单流程(2-3 步)
- 不要实时多人协作
- 不要复杂权限

如果学员选了「要做个全公司 OA」,劝他先做其中一个模块。

**Q:学员中文打字很慢,1 天做不完怎么办?**

A:可以用「实时语音转文字」工具(飞书妙记 / 通义听悟),或者让学员 2 人一组 1 个 demo(其中 1 人负责打字,1 人负责业务思考)。

**Q:学员的 demo 在手机上打不开?**

A:Skill 默认做移动端适配。如果学员做出来移动端不能用,讲师要现场演示「开发者工具 → 切到 iPhone 模式 → 看看哪里出问题」,让学员自己修。
