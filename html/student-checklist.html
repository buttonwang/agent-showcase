学员作业 checklist · 业务助手智能体

用法:把这份文件复制一份到你自己项目的 outputs/ 下,改名 checklist-<产品名>.md,边做边勾。
每一项的"判定标准"是红绿灯,打不上勾就回去重做,不要跳。
做完后,这份 checklist 就是你交付的"过程文档",可作为培训考核依据。

    6. 场景 C:重大改动重生成(目标 60 分钟以内)

    判定标准:冻结老版本、主版本 +1、写迁移函数、Breaking 标注、回滚方法齐全。

    6.1 30 秒判断:这是不是场景 C?

  • [ ] 改动影响 > 30% 代码,或 3 个以上模块
  • [ ] 改了核心流程,或改了数据结构
  • [ ] → 是场景 C

    • 6.2 冻结老版本

  • [ ] outputs/<产品名>/ 复制到 outputs/<产品名>-v-snapshot-YYYYMMDD/
  • [ ] 老 PRD 复制到 outputs/_archive/prd-<产品名>-v.md
  • [ ] 用户确认了冻结方案

    • 冻结后文件结构:

    
outputs/
├── <产品名>-v0.X-snapshot-YYYYMMDD/    ← 冻结的老版
├── _archive/
│   └── prd-<产品名>-v0.X.md            ← 冻结的 PRD
└── <产品名>/                            ← 即将写新版

    6.3 主版本号 +1

  • [ ] PRD 顶部版本从 v0.X → v1.0

    9. 自评打分

    9.1 完成度(每项 10 分,满分 70)

    9.2 质量分(每项 6 分,满分 30)

    (实际满分 30,这里写 36 是因为可以奖励 6 分给特别出色的项)

    9.3 总分

    完成度( / 70)+ 质量分( / 30)= 总分 / 100

    等级:

  • 90+:优秀,直接可交付生产
  • 75-89:良好,需要少量打磨
  • 60-74:合格,需要中等打磨
  • < 60:不合格,需要返工

    附录:常见挂科项

    最容易挂的 10 项(讲师评分时重点看):

  • PRD 写到对话里(必须写文件)
  • PRD 写完闷头生成 Demo(没等用户确认)
  • CRUD 是空架子(按钮在,提交没反应)
  • 改了字段没写 CHANGELOG
  • 改了字段没升 PRD 版本号
  • 改了字段没做数据兼容(老数据崩了)
  • 场景 C 没冻结老版本,出问题回不去
  • 场景 C 没写迁移函数,数据丢了
  • 主导航放右侧(用户已经明确要求左侧)
  • 视觉用了 emoji 当图标(用 lucide)

    • 每挂一项扣 5-10 分,直到扣完为止。
