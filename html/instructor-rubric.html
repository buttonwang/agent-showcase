讲师评分量表 · 100 分制

学员姓名:________________ 产品名:________________ 业务领域:________________ 评分日期:________________ 讲师姓名:________________

一、完成度(70 分)

每项 10 分,根据 checklist 自评 + 讲师复评给出。

评分细则(每项 10 分):

  • 9-10 分:完全做到,自查清单全勾,讲师复评无补充
  • 7-8 分:基本做到,自查清单 1-2 项没勾但有合理解释
  • 5-6 分:做了但有明显遗漏(比如没写 CHANGELOG)
  • 3-4 分:做了但流程不规范(比如没等用户确认)
  • 0-2 分:基本没做或完全错误

    • 二、质量分(30 分)

    每项 5 分。

    三、加分项(每项 +3,最多 +10)

  • [ ] 全程用 lucide 图标,零 emoji (+3)
  • [ ] 移动端能看,适配 375px (+3)
  • [ ] 多个模块联动正确(看板拖拽到详情页 / 表单选择联动等)(+3)
  • [ ] PRD 写得特别清楚,字段约束 / 业务规则写得很细(+3)
  • [ ] 给同事演示了 5 分钟,对方能独立上手(+3)
  • [ ] CHANGELOG 写得详细到能回放每次改动(+3)
  • [ ] 自己加了 smoke_test 没覆盖的检查项(+3)

    • 加分小计:____ (最多 +10)

    四、扣分项(每项 -5)

    讲师在学员交付物里发现以下任一项,直接扣分:

  • [ ] PRD 写到对话里,没写文件(-5)
  • [ ] PRD 写完没等用户确认就生成 Demo(-5)
  • [ ] CRUD 是空架子(按钮在,提交没反应)(-10)
  • [ ] 改了字段没升 PRD 版本号(-5)
  • [ ] 改了字段没写 CHANGELOG(-5)
  • [ ] 改了字段没做数据兼容,老数据崩了(-10)
  • [ ] 场景 C 没冻结老版本,出问题回不去(-5)
  • [ ] 场景 C 没写迁移函数,数据丢了(-10)
  • [ ] 主导航放右侧(-5)
  • [ ] 视觉用了 emoji 当图标(-3)
  • [ ] 用了没在 safelist 里的动态类名,导致样式没生效(-5)
  • [ ] 没做移动端适配(-3)
  • [ ] localStorage 没做版本号后缀,升级时数据冲突(-5)

    • 扣分小计:____

    五、总分

    完成度 + 质量分 + 加分 - 扣分 = ____ / 100

  • 75-89:良好,需要少量打磨
  • 60-74:合格,需要中等打磨
  • < 60:不合格,需要返工

    附录:评分时的「红牌」项

    以下任一项直接判「不合格」,无论其他做得多好:

  • CRUD 完全是空架子(整个 demo 不能用)
  • PRD 完全是空架子(只有一个标题)
  • 数据丢失且无法恢复(没做迁移 / 没备份)
  • 主导航放右侧(历史教训)
  • 用了大量 emoji 当图标(违反设计规范)
  • 没有 localStorage 持久化(刷新数据全丢)

    • 讲师可在评分时直接用「红牌」一票否决,而不必一项项扣分。
